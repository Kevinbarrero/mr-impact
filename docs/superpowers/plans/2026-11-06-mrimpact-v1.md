# mrimpact v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go CLI that, in a GitLab MR pipeline, finds the Go functions an MR changed, their callers, and the coverage of the added lines, then posts and updates one risk-ranked MR note.

**Architecture:** A pure analysis core (`diff` → `symbols` → `load`/`callgraph` → `coverage` → `risk` → `report`), orchestrated by `internal/pipeline`. Network I/O lives only in `internal/gitlab`, and the CLI lives in `cmd/mrimpact`. Call graph: `golang.org/x/tools` SSA + VTA, seeded with CHA.

**Tech Stack:** Go 1.26, `golang.org/x/tools` v0.52.0 (`go/packages`, `go/ssa`, `go/ssa/ssautil`, `go/callgraph/cha`, `go/callgraph/vta`, `cover`), standard library only otherwise (`flag`, `net/http`, `os/exec`, `go/ast`, `go/parser`, `go/printer`).

**Spec:** `docs/superpowers/specs/2026-11-06-mrimpact-design.md`

## Global Constraints

- Module path: `gitlab.com/wh1t3hat/mrimpact` (rename before first public push if the hosting changes).
- `go.mod`: `go 1.26.0`. The local `go1.22.5` auto-switches through `GOTOOLCHAIN=auto` (go1.26.10 is already cached). The CI image must be `golang:1.26`.
- No third-party dependencies besides `golang.org/x/tools`.
- Exit codes: `0` success/degraded (also on internal failure by default); `1` only with `--fail-on red` and ≥1 red; `2` only with `--strict` on internal failure.
- The note marker is exactly `<!-- mrimpact:v1 -->`.
- The token env var is `MRIMPACT_TOKEN` and is sent as the `PRIVATE-TOKEN` header.
- Defaults: `--depth 2`, `--timeout 5m`, `--out mrimpact-report.md`, diagram cap **20** nodes, caller list per function in the `<details>` section capped at **10** + `and N more`, table capped at **50** rows (+ "N more").
- Exclusions: paths with a `vendor/` segment, non-`.go` files, and files whose first comment group (before `package`) matches `^// Code generated .* DO NOT EDIT\.$`.
- Paths everywhere are repo-relative and slash-separated.
- The risk legend text lives in one constant (`risk.Legend`) used by the report footer:
  `🔴 untested with callers, or exported signature changed · 🟡 partial, or untested with no callers · 🟢 covered`
- Version constant: `pipeline.Version = "0.1.0"`, shown as `mrimpact v0.1.0`.

## Review Focus

1. **Multiple `init()` funcs or same-named funcs across build-tagged files in one package**: keys must not collide. Each `init` gets its own key (`init#1`, `init#2` by source order), and a function with no matching BASE key is `new`, never mis-paired. Test in Task 3.
2. **Body change that only deletes lines (0 added lines) under a coverprofile**: coverage is `n/a`, and risk falls back to the static `TestReached` signal instead of reading 0/0 as "0 % covered → red". Test in Task 6.
3. **Changed function that SSA cannot locate** (e.g. a file excluded by build tags, or a package that failed to load): it must appear under "not analyzed", not silently disappear and not crash. Test in Task 4 (Impact.Found=false) and Task 9 (e2e build-tags case).
4. **Mermaid-hostile names** (generics `List[T]`, pointer receivers `(*T)`, quote characters): labels must be quoted/escaped and node IDs synthetic (`n0`, `n1`…), so GitLab never shows "Unable to render". Test in Task 7.
5. **Pagination when the marker note is not on page 1** (busy MRs with >100 notes): it must find the note and update it instead of creating a duplicate on every push. Test in Task 8.

### Task 3: Changed-function detection (AST)

**Files:**
- Create: `internal/symbols/symbols.go`, `internal/symbols/symbols_test.go`

**Interfaces:**
- Consumes: `diff.FileChange`.
- Produces:
```go
package symbols
type Kind string
const (New Kind = "new"; Body Kind = "body"; Signature Kind = "signature"; Deleted Kind = "deleted")
type ChangedFunc struct {
    Key        string // dir + "." + [recvTypeName + "."] + name, init funcs as "init#N"; e.g. "pricing.Calculator.Total"
    Display    string // pkgname-qualified, e.g. "pricing.(*Calculator).Total", "orders.applyDiscount", "list.(*List[T]).Push"
    File       string // HEAD path (BASE path if Deleted)
    StartLine  int    // FuncDecl position line (HEAD, or BASE if Deleted)
    Kind       Kind
    Exported   bool   // name exported AND (no receiver OR receiver type exported)
    AddedLines []int  // added HEAD lines inside the decl range
    IsTest     bool
}
type DeclChange struct{ File string; Line int; What string } // What: "import", "type Foo", "var x", "const y"
type Result struct{ Funcs []ChangedFunc; Decls []DeclChange; TestsTouched []string }
type Source func(path string) ([]byte, error) // must return an error wrapping fs.ErrNotExist when absent
func Find(changes []diff.FileChange, head, base Source) (Result, error)
```

Rules:
- Only `IsTest == false` changes produce `Funcs`/`Decls`; test files go to `TestsTouched` (HEAD path, or OldPath if deleted).
- A HEAD func is changed if any `AddedLines` fall in its `[Pos, End]` line range, **or** any `DeletedLines` fall in the range of the BASE func with the same Key. The BASE file is `OldPath`.
- `Kind`: Key absent in BASE → `New`. Present, with differing `go/printer` output of receiver type + `FuncDecl.Type` → `Signature`. Otherwise → `Body`.
- BASE funcs whose Key is absent in HEAD → `Deleted`. This covers deleted files and funcs removed from modified files. If HEAD has the same Key in a different file (moved), it's a pair, not a deletion.
- Changed lines inside no FuncDecl → one `DeclChange` per affected top-level `GenDecl` (deduplicated).
- Output is sorted by File, then StartLine.

### Task 7: Markdown + Mermaid report

**Files:**
- Create: `internal/report/report.go`, `internal/report/report_test.go`, `internal/report/testdata/*.golden.md`

**Interfaces:**
- Consumes: `risk.Level`, `risk.Legend`, `callgraph.Caller`.
- Produces:
```go
package report
const Marker = "<!-- mrimpact:v1 -->"
type FuncRow struct {
    Level       risk.Level
    Display     string
    Kind        string // "new" | "body" | "signature" | "signature (exported)"
    Callers     []callgraph.Caller
    CoverText   string // "0 % (0/12)", "n/a", "reached by test", "not reached"
}
type Model struct {
    Funcs        []FuncRow // unsorted; Render sorts by Level desc, len(Callers) desc, Display
    Deleted      []string
    Decls        []string
    TestsTouched []string
    NotAnalyzed  []string // "orders.Special (build tags)", "pkg/x (load error)"
    Warnings     []string // stale coverage, timeout, etc.
    Coverage     string   // "coverprofile" | "static"
    BaseSHA      string   // rendered as first 7 chars
    Degraded     bool
    Failure      string   // non-empty → render only marker + "couldn't analyze: <Failure>" + footer
    NoGoChanges  bool     // → marker + "No Go code changes" + footer
    Version      string
    Duration     time.Duration // rendered with one decimal second, "3.2 s"
}
func Render(m Model) string
```
The format follows spec §6 exactly, in that order: title `### 🔍 MR impact — N functions changed`; summary `**🔴 a · 🟡 b · 🟢 c** · coverage: \`X\` · base \`sha7\``, with ` · ⚠️ degraded` appended when Degraded. Table columns: `Risk | Function | Change | Callers | Added-line coverage`. The Callers cell is `N (P pkgs)` (P = distinct `Caller.Pkg`), or `0`. Then the ➖/🧪/declarations lines, but only when non-empty. The Mermaid block is `graph RL` with synthetic IDs `n0..`, labels `"<emoji> <Display>"` escaped (`"` → `#quot;`), edges caller → changed func (depth-1 edges only, plus depth-2 edges to depth-1 callers), at most 20 nodes, highest-risk funcs first; if capped, a `%% +N not shown` comment and a line `+N nodes not shown` under the diagram. Then `<details><summary>All callers (T)</summary>`, then `<details><summary>⚠️ Limits of this analysis</summary>`, which always holds the two fixed bullets from spec §6 plus NotAnalyzed and Warnings. Footer: `<sub>Rules: {risk.Legend} · mrimpact v{Version} · {Duration}</sub>`.
